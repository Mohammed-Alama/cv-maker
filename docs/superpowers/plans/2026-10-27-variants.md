# Job Variants + Repo Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add standalone per-job CV variants addressed by `--variant TAG` (each with its own output folder and archive history) and put a rendered preview of the CV on the README.

**Architecture:** A tiny new `variants.py` owns the tag rule and the path layout (`variants/<tag>.json` → `output/<tag>/`), so `generate.py`, `verify_ats.py` and `validate_data.py` resolve variants the same way. Generation itself is untouched: a variant is just a different `(data, output_dir)` pair through the existing temp-swap and archive code. The preview is a committed PNG rendered from the base PDF, not a build step.

**Tech Stack:** Python 3.10+, ReportLab, pdfplumber/pypdfium2 (already installed), pytest, GNU make.

**Spec:** `docs/superpowers/specs/2026-10-27-variants-design.md`

**Spec deviations:** tag resolution lives in `variants.py` rather than `generate.py` because `verify_ats.py` and `validate_data.py` need the same rule and must not import ReportLab. `make variant` calls `validate_data.py --variant` instead of `--yaml-path variants/<tag>.json`, so a hostile `V` is rejected before any file is read; `--yaml-path` remains for arbitrary files.

## Global Constraints

- Tag format is `^[a-z0-9][a-z0-9-]*$`; anything else exits 2 with the offending tag in the message and touches no file.
- Variant input is `variants/<tag>.json`, a complete CV document with the same schema as `data.json`. No overlay or inheritance.
- Variant output is `output/<tag>/<stem>.pdf`; `<stem>` comes from `cv.config.json`, never from the tag.
- Archives follow the existing rules and stay beside the PDF they replaced, i.e. inside `output/<tag>/`.
- `make all` stays base-only and must never generate, verify or archive a variant.
- ATS required terms stay global (`cv.config.json`); a variant missing one fails `verify` with exit 1.
- No per-variant config files, no new dependencies, no CI.
- Config errors and variant errors print one line to stderr and exit 2; a missing PDF in `verify_ats.py` exits 1.
- Every task ends with `.venv/bin/python -m pytest -q` green and its own commit.

## Review Focus

1. **Hostile tags** — `--variant ../escape`, `ACME`, `acme.json`, `acme/2`, `""`, `-acme`, `..` must exit 2 and read/write nothing outside `variants/` and `output/`. Pinned in Task 1 (parametrized `variant_path`/`output_dir_for` tests) and Task 2 (CLI exit 2).
2. **Missing or malformed variant file** — `--variant nope` and a broken JSON file must produce one stderr line naming the file and exit 2, never a traceback or a partial PDF. Pinned in Task 2.
3. **Base PDF safety** — a variant run must not archive, overwrite or delete `output/<stem>.pdf`. Pinned in Task 2 (CLI test with a pre-existing base PDF) and Task 4 (end-to-end check).
4. **Verifier targets the variant** — `verify_ats.py --variant acme` must read `output/acme/<stem>.pdf` and, when absent, hint `--variant acme` in the "not found" message. Pinned in Task 3.
5. **Validator targets the variant** — `validate_data.py --variant acme` must validate `variants/acme.json`, not `data.json`, and reject a bad tag before reading any file. Pinned in Task 3.

**Interfaces:**
- Produces:
